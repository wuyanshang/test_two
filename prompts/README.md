# 提示词文件说明

本目录包含用于语义歧义检测的提示词文件。

## 📁 文件列表

### 原始版本
- **semantic-ambiguity.txt** - 原始的完整提示词（单阶段）

### 修复版本（推荐使用）
- **stage1-fixed.txt** - 修复版阶段一：消歧判断
- **stage2-fixed.txt** - 修复版阶段二：歧义分类

### Kimi 优化版本
- **stage1-kimi.txt** - Kimi 优化版阶段一（紧凑格式）
- **stage2-kimi.txt** - Kimi 优化版阶段二（紧凑格式）

## 🔧 版本说明

### 原始版本 vs 修复版本

**原始版本的问题：**
1. ❌ 中文名清晰 + 英文名矛盾的情况会被漏报
   - 例：field_cn="投保人姓名", field_en="sex" → 原始版判断为无歧义
2. ❌ 技术性修饰语（"字段1"、"信息"）被误判为业务限定
   - 例：field_cn="金额字段1" → 原始版判断为无歧义

**修复版本的改进：**
1. ✅ 在阶段一增加了中英文矛盾检测
2. ✅ 明确定义了"业务限定修饰语"
3. ✅ 增加了业务概念分类，识别严重矛盾

### 修复版本 vs Kimi 优化版本

**修复版本：**
- 结构化清晰（XML 标签）
- 详细的步骤说明
- 适合理解和调试
- 字符数：~7,400

**Kimi 优化版本：**
- 紧凑的表格格式
- 信息密度高
- Token 效率更高
- 字符数：~5,800

## 🎯 使用建议

### 对比测试
使用 `comparison_workflow.py` 对比原始版本和修复版本：
```bash
python comparison_workflow.py test_data.xlsx
```

### 生产环境
推荐使用 **修复版本**（stage1-fixed.txt + stage2-fixed.txt）：
- 功能正确，修复了已知 bug
- 逻辑清晰，易于维护
- 适配 Kimi-2.6

### Token 优化场景
如果需要降低 Token 成本，使用 **Kimi 优化版本**：
- 保持相同的逻辑
- 更紧凑的格式
- 减少 ~22% 的 Token 消耗

## 🔄 版本历史

### v1.0 - 原始版本
- 单阶段判断
- 中文名权威性原则（过于绝对）

### v2.0 - 修复版本
- 拆分为两阶段
- 增加矛盾检测
- 明确业务限定修饰语定义

### v2.1 - Kimi 优化版本
- 保持修复版本的逻辑
- 优化格式，提高 Token 效率
- 专门适配 Kimi-2.6

## 📝 自定义提示词

如果需要自定义提示词：

1. 复制对应的版本文件
2. 修改规则或判断逻辑
3. 使用 `comparison_workflow.py` 测试效果
4. 对比原版本，验证改进

## ⚠️ 注意事项

1. **不要混用不同版本**
   - 阶段一和阶段二必须使用同一版本
   - 例如：stage1-fixed.txt 必须配合 stage2-fixed.txt

2. **修改后需要测试**
   - 任何修改都可能影响判断准确性
   - 建议使用测试工具验证

3. **保持编码一致**
   - 所有文件使用 UTF-8 编码
   - 避免中文乱码问题
